# JARVIS LLM 10.12 — generation, evaluation and checkpoints

## State after implementation

Educational Java 21 decoder-only character transformer with teacher-forced training from 10.11.
The 10.12 API adds:

- `TextGenerator.generate(prompt, maxNewTokens, temperature, seed)` — bounded decoding and EOS termination. `temperature=0` is greedy; >0 samples probabilities in a reproducible way for a fixed seed.
- `ModelEvaluator.evaluate(examples)` — corpus-wide next-token mean cross entropy and perplexity, weighted by target tokens. Does not mutate model weights.
- `ModelCheckpoint.save(path, trainer)` and `.load(path, trainer)` — version 1 binary checkpoint with all trainable tensors, vocabulary identity, context length, optimizer hyperparameters and AdamW steps/moments, plus a SHA-256 integrity checksum.

## Mathematical definitions

For teacher forcing with N target tokens, mean cross entropy:

    L = (1/N) Σ_{t=1..N} -log p(target_t | prefix_t)

Perplexity:

    PPL = exp(L)

Perplexity 1 is ideal on the measured corpus. Evaluation on the same data as training can be misleading; use held-out data for assessing generalization.

For temperature T>0, sampling distribution is:

    q_i ∝ exp(log(p_i)/T)

`T=0` chooses the highest-probability allowed token. PAD/UNK/BOS are excluded; EOS terminates generation. If the current context is full, generation stops without exceeding the model's configured maximum. No sliding-window context is implemented yet.

## Checkpoint layout and safety

- Fixed magic, format version, learning rate, weight decay, gradient clipping configuration.
- Context size and explicit vocabulary code points to avoid mixing incompatible token IDs.
- Ordered tensors for token/positional embeddings, all transformer block norms, head Q/K/V projections, attention output projection, FFN, final LayerNorm, LM Head.
- AdamW moments m/v and optimizer step counter for each parameter vector, including individual weight matrix rows.
- SHA-256 checksum at end; temporary file in the destination directory; atomic rename when available.
- Loader checks checksum, architecture, shapes, vocabulary, finiteness and optimizer key layout **before** applying parameters.

The checksum protects against accidental corruption but DOES NOT authenticate the author. Never load a checkpoint from an untrusted source. No arbitrary Java object deserialization is used. The current educational implementation caps checkpoint size at 64 MiB and requires a *pre-created matching architecture*; it does not reconstruct the model or tokenizer automatically. If a filesystem does not support atomic rename, the writer falls back to a regular replace operation.

**Important:** Do not train, generate or load/save simultaneously on the same mutable model. The Spring service added next must use an explicit model lock or a single-threaded training queue. Trained weights are stored on disk, with paths/version metadata in PostgreSQL.

## Running the demo

From `backend/`:

    ./mvnw.cmd -Dtest=TextGeneratorTest,ModelEvaluatorTest,ModelCheckpointTest test
    ./mvnw.cmd clean test
    ./mvnw.cmd -DskipTests compile
    java -cp target/classes pl.bawar.jarvis.brain.training.CheckpointDemo

Produces `backend/checkpoints/jarvis-tiny-v1.ckpt`. Add `backend/checkpoints/` or `*.ckpt` to `.gitignore` before running; do not commit trained weights automatically.

## Known limitations / next steps

1. Small char-token model; does not possess useful general language knowledge or internet knowledge.
2. Checkpoints require a model instance initialized with the same vocabulary and architecture; importing arbitrary models or auto-resizing vocab is unsupported.
3. Temperature sampling only; no top-k/top-p, no sliding window, no beam search.
4. AdamW model updater from 10.11 is still an educational CPU implementation; full transactional recoverability is not guaranteed on JVM process crashes.
5. No Java API or chat persistence in this lesson. Next: BE-1 Spring Boot service facade, Flyway/PostgreSQL conversations and messages, secured Electron bridge and Angular ChatStore wiring, full E2E tests.
6. Internet search later via controlled Spring Boot tool, with citations, timeouts, SSRF checks and no automatic weight updates.
