# BE 11.3 — REST API for Jarvis chats

## Architecture

```text
Client (future Angular/Electron)
    -> Spring Security (authentication) + @PreAuthorize
    -> ChatController
    -> ChatApplicationService
       -> ChatPersistenceService.getConversation()
       -> JarvisModelService.generate() [single model lock]
       -> ChatExchangeWriter.appendTurn() [@Transactional]
          -> ChatPersistenceService.appendMessage(USER)
          -> ChatPersistenceService.appendMessage(ASSISTANT)
          -> PostgreSQL [jarvis_messages]
```

- `ChatController` handles HTTP/DTO only.
- `ChatApplicationService` orchestrates one chat turn. `ReentrantLock` serializes requests in this JVM; the model itself additionally uses its own lock.
- `ChatExchangeWriter` is a separate Spring bean: its transactional proxy wraps both database inserts, unlike a self-invoked `@Transactional` method.
- No transaction spans inference. On LLM error, no message is inserted. The user message and AI response are atomic in the database.
- The reply is a tiny-model continuation, not a cloud LLM response. `temperature=0` and `seed=42` make this initial educational flow deterministic.

## Context budget

`model.status().contextLength()` is the max number of input tokens, including BOS. The app limits prompt to the last `context-1-32` code points (at least 1), reserving room for 32 new tokens. This is a first approximation for the current character tokenizer; it is not a generalized BPE token budget. The full message is still persisted.

## Security limitations

- `@EnableMethodSecurity` and `@PreAuthorize("isAuthenticated()")` are explicit backstops. Existing HTTP filters and CSRF configuration remain untouched.
- This implementation is **single-user local**; conversations have no ownership field. Any permitted authenticated identity can see all chats. Do not publish as shared multi-user service.
- Check 401/403 with unauthenticated request. When integrating Angular/Electron, design secure auth transport rather than embedding passwords in the renderer.
- Use loopback binding, secure IPC and input-size/rate controls; a bound request queue is a future improvement.
